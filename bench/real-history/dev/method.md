# Methods: expanded action review and archived step-1 diagnosis

## Step 2: expanded evidence, not a model change

The current report is generated by `scripts/render-real-history-actions.ts`,
reusing the existing separation implementation. `families.json` counts each
positive repo/commit event once and lists all correlated member pairs. Every
family has an explicit action class; unknown cases are withheld from supervision.
Related-different examples come exclusively from reviewed real permissive-detector
findings, not automatically from failed mining proposals.

New windows and the TypeScript 200KB per-source mining cap are explicit in
`repos.json`. Oversize revision:file exclusions are retained in its mining audit.
The initial unbounded TypeScript attempt was stopped for excessive cost, then
restarted with that cap; it is not counted as a second history search. New normal
samples use `GW_REAL_HISTORY_NORMAL_LIMIT=2`; original samples are preserved.
The fallback metadata audit in replay uses the same dates, keyword predicate and
production paths while a full proposal-mining run is still in progress.

Direct-reuse labels require an unchanged existing target file/name/body hash,
an after-caller source witness, and a whole-body direct-call AST check. Human-like
agent review must still verify binding identity, arguments, returned value,
validation and observable effects; the mechanical guard is not a proof of semantic
equivalence. Newly created shared modules and extended parents are extract/extend,
never direct positives merely because copied code looks identical.

To reproduce the added search with existing dependencies/clones:

```sh
node --import tsx scripts/real-history-dev.ts setup
for repo in typescript vite vue pandas; do
  node --import tsx scripts/real-history-dev.ts mine "$repo"
  GW_REAL_HISTORY_NORMAL_LIMIT=2 node --import tsx scripts/real-history-dev.ts replay "$repo"
done
node --import tsx scripts/real-history-diagnose.ts catalog
node --import tsx scripts/real-history-diagnose.ts positives
node --import tsx scripts/real-history-diagnose.ts labels
for repo in zod pydantic django scikit-learn typescript-eslint typescript vite vue pandas; do
  node --import tsx scripts/real-history-diagnose.ts features "$repo"
done
node --import tsx scripts/render-real-history-actions.ts
```

The following sections describe the initial step-1 slice at commit `7e6d9e6`;
their four-family counts are historical, not the expanded report's totals.

## What this evidence does and does not establish

This is a deliberately enriched **development** case-control set, agent-reviewed,
not human-approved. The frozen detector is the follow-up branch base `342e156`;
the permissive candidate source is `ca55316`. No detector, model, threshold,
schema, CLI, hook or existing calibration/final-evaluation artifact changes here.
The three reserved repositories (got/click/pytest) were not queried or replayed.

The usable reference set is 24 positive **pairs**, but only four positive refactor
families: 21 combinations of seven array-backend predicates, two Django production
consolidations, and one Django test-only consolidation. The vendored array-api
compatibility code has its own **MIT** license, checked at the pin; the enclosing
scikit-learn repository is BSD-3-Clause. Both before sites exist at the same parent
revision. None is a planted example or a before/after self-pair masquerading as
two simultaneously existing implementations.

**The development set is not yet large/diverse enough to train a BLOCK model.**
There are no TS positive families and no positive proving safe unchanged
direct-call replacement. Claiming 24 independent positive examples would be
misleading. Even the 23 production-path positive pairs represent just three
families. This is an evidence/diagnosis checkpoint, not completion of the eventual
real-history precision/recall objective.

The 33 selected negatives are strict rejections from 118 permissive normal-commit
duplicate candidates. Eight are verified lexical containment; the rest were
chosen for inspectable contracts, including version/generated boundaries and
two high-structure Zod cases. Both sites' code and the normal commit's changed
context were inspected. This is not a random sample of all findings. The other
85 normal pairs are **unlabelled**, not implicitly negative. Raw miner proposals
are likewise not labels. Three Django core runs exceeded the 120-second budget;
they remain explicitly unavailable rather than counted as clean commits.

## Mining protocol and rejected shortcuts

1. Clone the five manifest URLs externally, without shallow history. Pins bound
   January–June 2025. Walk reachable non-merge commits whose **committer** date is
   inside that UTC calendar window, recording each commit and its first parent.
2. Mine changed production TS/Python functions/methods. A body becoming a short
   existing call, a removed body with another call added, or two bodies delegating
   to one new helper, or two removed bodies matching one newly called helper,
   is a **proposal**. Existing definitions (including const/let arrow helpers)
   are searched in the parent snapshot, including unchanged files. Same-file
   unchanged relocations are screened out; cross-module moves can still produce
   false proposals and require strict review.
   Call-name matching is not binding resolution. Parsing failures, arrows outside
   searched definitions, renames, non-short wrappers and the structure proposal
   cutoff can all hide positives; mining recall is unknown.
3. Read refactoring diffs, not just subjects or similarity scores. The selected
   mail commit explicitly extracts `_send_server_message(setting_name=...)`;
   expression resolution moves validation to BaseExpression and removes Func's
   override; logging assertions extend a mixin before replacing all old calls;
   array predicates retain backend-specific behavior around a new common helper.
   All seven predicate bodies were reviewed; pair combinations share that proof.
4. Test-path mining is supplementary and keyword-enriched. Only the actual
   logging assertion consolidation is retained. A removed ColumnTransformer
   test merged after deleting a deprecated feature is **not** proof that its
   before-state behavior was interchangeable with the survivor. No label was
   assigned from that commit alone.
5. An apparent typescript-eslint `isUnderlyingTypeString -> isStringLike` match
   was rejected: the short-name search found a same-spelled function in another
   rule, while the diff introduced a new local helper. Similarity and a matching
   call spelling do not establish the callee's identity. Zod's large locale
   relocation is likewise not a mass of author-confirmed deduplications.
   A broader both-deleted-body scan also finds Pydantic's alias-generator pair
   at `d992117243b3d44047ef37f9d7d75243bb98dbca`, with structure 0.859. The
   diff moves them into two separate implementations, not one shared helper;
   it is not counted as a positive merely because both bodies moved.
6. Normal-commit candidate sampling is fixed by `SHA256(normal-v1:<commit>)`,
   excluding refactor keywords and commits with no production-path change.
   Limits of 12/12/12/4/4 were chosen for replay cost, before interpreting their
   findings. Candidate replay uses the built old API with an explicit 120 s
   timeout; these are real unchanged detector decisions, not a reimplementation.

Every labelled pair has exact revisions, file/line ranges, kinds and SHA-256
source-span hashes. Positives also reference the actual post-refactor helper.
Hashes and locations were checked against the external Git object databases.
No upstream function bodies or downloaded models are committed.

## Causal diagnosis, with limits

- **The output action is stronger than the evidence.** In the captured permissive
  `zod-normal.json`, commit `7ed0c3694d...` emits a BLOCK for `datetime ->
  datetimeRegex`, with `exact=1`, vocabulary approximately 0.997, and a literal
  “Replace the body ... with a call” fix. The source at that exact commit accepts
  hours-only offsets in the v4 expression, while the v3 expression requires
  minutes. Replacing it would undo the change. This verifies an executed chain
  from a real replayed commit, through a coarse fingerprint collision, to an
  invalid recommendation; it is not merely a hypothetical path. The committed
  current signals show whether the frozen follow-up policy still accepts it.
  The report does **not** infer an actual current CLI emission from a pair score:
  retrieval, ranking and whole-check behavior were not replayed on that baseline.
- **Author deduplication is not unchanged-call equivalence.** Before-state
  `mail_admins` and `mail_managers` select different recipient settings; the diff
  introduces a setting-name parameter instead of calling one wrapper from the
  other. BaseExpression first gains missing validation before Func's override
  disappears. Logging's survivor gains missing checks and a return value. These
  observed diffs disprove the tempting hypothesis that every author-refactor
  positive is already a safe direct replacement.
- **Identical structure does not identify bindings, state or return contracts.**
  Enum parsing versus unconditional bigint-error creation, AST predicates versus
  reporting visitors, and path getters versus program construction are all
  actual permissive findings with incompatible observed behavior. The formatter
  case additionally proposes a nested closure from a different module: its free
  variables and issue representation do not match the caller. Current same-file
  containment checks do not by themselves establish cross-module substitutability.
- **Requested contract features are useful but insufficient.** Receiver/member
  paths and return/call sets can distinguish many false matches, but local-copy
  writes are not necessarily observable effects, aliases/imports are unresolved,
  dynamic calls can raise or mutate, and current syntactic prototypes deliberately
  omit nested function bodies. Missing features are unknown, not agreement.
  Literal mismatches explain the offset counterexample, but also occur in valid
  backend/recipient helper extraction. A blanket no-literal-differences rule
  would confuse action modes. Separation tables expose these limitations rather
  than hiding empty sets as perfect matches.

The dataset is strongly confounded by language, repository, within-file mining,
test versus production population and one large combinatorial family. Raw AUC
is not generalization evidence; even family-balanced AUC has only four positive
families and no uncertainty claim. No feature weights/cutoffs were selected.

## Recommended architecture, not an implemented detector change

1. **Keep current independence/kind safeguards.** They are structural correctness
   rules, not learned exceptions. Keep the present detector frozen during further
   evidence collection.
2. **Predict the action, not just “duplicate”.** Separate `direct reuse`,
   `extract/extend helper`, `related but distinct`, and `unknown`. The current
   dataset provides evidence for helper actions and negatives, but cannot train
   the direct-reuse head. A suggestion to extract a parameterized helper must not
   render an unsupported call to either old wrapper.
3. **Build binding- and role-aware contracts.** Resolve callees/imports and
   receiver owners; distinguish argument/SELF/global writes from fresh-local
   mutations; preserve static dictionary keys, return provenance, await/yield,
   literal predicates and exception/validation paths. Record unknown effects,
   external I/O and free variables explicitly. For direct reuse, require a
   supported input/argument mapping and compatible observable effects and outputs.
   Different state targets are not automatically a veto for helper extraction.
4. **Prefer an interpretable small model after collecting more independent
   supervision.** Start with calibrated logistic/action-specific scores and
   explicit unknown abstention, not a high-capacity classifier. Normalize effects
   by semantic role, use family weighting, and evaluate with entire refactor
   families and repositories held out. Do not random-split the 21 backend pairs.
   Collect independent TS positives and direct-call positives; target at least
   20 independent development refactor families before meaningful calibration.
   Existing planted OOF precision remains a separate regression check, not a
   substitute for history evidence.
5. **Measure retrieval and action quality separately.** Current reported positive
   sensitivity is conditional on manually supplying a pair; no positive-commit
   end-to-end replay was performed. Candidate top-k competition, token/test
   exclusions and changed-symbol scope can lower actual recall. A recall estimate
   needs a defined manually reviewed opportunity frame and must state its mining
   and eligibility limitations. Never divide by just the findings that fired.
6. **Freeze before final evaluation.** Keep reserved repos/windows untouched until
   the detector/action contract and scoring are frozen. Seek at least 20 held-out
   BLOCK findings with real independent event diversity, reviewing every finding
   strictly. Report TP/FP precision and uncertainty, plus recall only where a
   defensible opportunity denominator exists. A quiet detector or many correlated
   pair combinations cannot establish the ≥90% real-history gate.

## Reproduction (dev-only; networking only for explicit setup/install)

Run from the GroundWork repository with dependencies installed:

```sh
export GW_REAL_HISTORY_CACHE="${GW_REAL_HISTORY_CACHE:-$HOME/work/gw-real-history}"
node --import tsx scripts/real-history-dev.ts setup
# In "$GW_REAL_HISTORY_CACHE/permissive-detector": npm ci && npm run build
for repo in zod pydantic django scikit-learn typescript-eslint; do
  node --import tsx scripts/real-history-dev.ts mine "$repo"
  node --import tsx scripts/real-history-dev.ts replay "$repo"
done
for repo in pydantic django scikit-learn typescript-eslint; do
  node --import tsx scripts/real-history-dev.ts mine-tests "$repo"
done
node --import tsx scripts/real-history-diagnose.ts catalog
node --import tsx scripts/real-history-diagnose.ts positives
node --import tsx scripts/real-history-diagnose.ts labels
for repo in zod pydantic django scikit-learn typescript-eslint; do
  node --import tsx scripts/real-history-diagnose.ts features "$repo"
done
node --import tsx scripts/render-real-history-dev.ts
npm run typecheck && npm test && npm run build && npm run selftest -- --through 4 --quick
```

`setup` verifies full-history clones and pinned license files. It does not install
or execute upstream projects. The legacy detector build is an isolated external
worktree. Replays/features use detached worktrees, never rewrite clone history,
and may produce timing differences. Labels are explicit agent judgments, not
automatically derived from similarity. `repair-locations` was used once to update
early raw-mining location metadata to the extractor's `startLine` field and
validate all 1,962 references; fresh mining writes it directly. `contracts`
recomputes only exploratory contracts from already scored source references.
Published package contents exclude these scripts and development artifacts;
selftest does not clone, mine, infer new labels or consume this dev set as a gate.
